# NexusTavern — План Оптимизации под Большие Библиотеки (800+ Персонажей и 3 000+ Чатов)

Данный документ фиксирует новый пошаговый план устранения высокого энергопотребления CPU/APU (до **35 Вт** на процессоре уровня **AMD Ryzen 7 8845HS**, 8 ядер / 16 потоков, Radeon 780M) и фризов прокрутки во всём интерфейсе при загрузке крупной пользовательской базы (**800+ карточек персонажей** и **3 000+ `.jsonl` чатов**).

Все работы проводятся в строгом соответствии с архитектурой и правилами из **[PROJECT.md](./PROJECT.md)**.

---

## 1. Диагностика проблемы и целевые метрики

По результатам аудита кодовой базы выявлены 6 корневых причин деградации производительности:
1. **`ScrollIndicator` на всех панелях**: синхронное чтение геометрии (`scrollHeight / clientHeight / scrollTop`) и `setState` на каждый тик `scroll` без `requestAnimationFrame` + подписка `ResizeObserver` на **каждого прямого ребёнка** всех скролл-областей и `MutationObserver`.
2. **Раздувание DOM и GPU-слоёв в списках (`CharacterGallery`, `TimelineBranchList`, `.bb-pinned-slot`)**: бесконечное накопление карточек в DOM при скролле вниз без виртуализации / `content-visibility: auto`, рендер всех групп/веток чатов разом, глобальный `will-change: transform` на всех `.bb-pinned-slot` в покое (800+ композитных текстур) и тяжёлые селекторы `:has(.bb-kebab-menu.is-open)`.
3. **Непрерывная нагрузка на композитор и APU (CPU + iGPU)**: WebGL-шейдер `PearlescentShader` работает без лимита FPS (120/144/165 Гц), аватар последнего сообщения бесконечно анимирует некомпозитный `box-shadow` (`bb-avatar-float` -> repaint каждые 16 мс), а полупрозрачные боковые тома (`.bb-tome` с `position: absolute; height: 100dvh; backdrop-filter: blur(...)`) и `mask-image` на ленте чата заставляют GPU пересчитывать размытие всей сцены на каждый кадр скролла.
4. **Блокировка главного потока Node.js (Event Loop)**: попиксельное декодирование и ресайз PNG-миниатюр на чистом JS синхронно в основном потоке (`thumbnails.js`), синхронные дисковые обходы при холодном/инвалидированном кэше карточек и чатов, а также полные перезапросы `GET /api/characters` (все 800 карточек) после создания/удаления одиночного чата.
5. **Лишние `O(N)` / `O(N log N)` пересчёты в React при 800 карточках**: двойная фильтрация и сортировка карточек (`useScenarioWorkspace` + `CharacterGallery`) с тысячами вызовов `Date.parse()` внутри `Array.sort`, пересборка `cardsByAvatar` в закрытом `PersonaPicker` (внутри `ChatComposer`) и дублирование `buildTimelineForest` между `TimelineBranchList` и `ChatViewport`.
6. **Конфигурация dev-окружения (`vite.config.js`, `package.json`)**: отсутствие `data/**` в `server.watch.ignored`, из-за чего файловый watcher следит за 3 800+ пользовательскими файлами, и параллельный фоновый запуск `vite build --watch` в `npm run dev`.

| Показатель (база: 800 карточек, 3 000 чатов) | Текущее состояние (Baseline) | Целевое состояние (Target) |
| :--- | :--- | :--- |
| **Потребление APU в покое / при чтении** | Постоянная фоновая нагрузка (15–35 Вт на Ryzen 7 8845HS) | `< 3–5 Вт` в покое, `0` лишних repaint в секунду |
| **Плавность скролла во всех панелях и чате** | Фризы, просадки FPS и forced reflow на каждый тик колеса | Стабильные `60 / 120 / 165 FPS` (`< 2–3 мс` на кадр Main Thread) |
| **Живые DOM-узлы и композитные слои галереи** | До `800+` карточек в DOM и `800+` `will-change` слоёв | Виртуализация / `content-visibility: auto`, `0` лишних `will-change` слоёв в покое |
| **Генерация 800 PNG-миниатюр на сервере** | Блокировка Event Loop Node.js на десятки секунд | Вынос в `node:worker_threads` с очередью конкурентности, `0 мс` блокировки API |
| **Мутации чата (создание / удаление / сообщение)** | Полный перезапрос `GET /api/characters` (800 карточек) | Точечный локальный/дельта-апдейт 1 карточки за `< 5 мс` |

## 2. Регламент выполнения плана

1. **Строгая атомарность**: каждый подшаг (`P1.1`, `P1.2` и т.д.) выполняется отдельно, без смешивания оптимизаций с новыми фичами.
2. **Никаких регрессий совместимости и визуала**: 100% обратная совместимость с форматами SillyTavern (`chara`/`ccv3`, `.jsonl`, пресеты, `RegexScriptData`, `settings.json`) и сохранение эстетики M3 / NexusTavern.
3. **Никаких сторонних runtime-зависимостей**: используем нативные возможности браузера, CSS Containment, React 19, Vite 6 и встроенные модули Node.js (`node:worker_threads`, `node:fs/promises`).
4. **Обязательная проверка после каждого шага**: прогон `npm run lint`, `npm test`, `npm run build` и живая проверка под нагрузкой перед переходом к следующему этапу.

## 3. Пошаговый план работ

### Этап P1. Плавность скролла во всём интерфейсе (`ScrollIndicator` и скролл-контейнеры)

- [x] **Шаг P1.1 — Полный рефакторинг `ScrollIndicator` на `requestAnimationFrame` + прямая мутация DOM без React-стейта (`src/ui/atoms/ScrollIndicator/ScrollIndicator.jsx`)**:
  - Убрать синхронный вызов `sync()` и `setThumb` / `setVisible` на каждый пиксель события `scroll`.
  - Перевести обновление позиции и высоты ползунка на батчинг через **один `requestAnimationFrame` на кадр** с прямой записью в `thumbRef.current.style.transform = translate3d(0, ${top}px, 0)` и `style.height` (без ререндера React-компонента при прокрутке).
  - Убрать цикл подписки `ResizeObserver` на **все дочерние узлы** (`for (const child of el.children) ro.observe(child)`) и каскадный `MutationObserver` — наблюдать только за самим контейнером `el` и пересчитывать геометрию лениво в `rAF`.
  - **Живая проверка**: быстрая прокрутка колесом и перетаскивание ползунка в ленте чата, галерее на 800 карточек, списке чатов и настройках — `0` React-ререндеров и `0` forced reflow вне `rAF`.

### Этап P3. Снижение энергопотребления APU/GPU с 35 Вт до минимума (Шейдеры, Repaint и Backdrop Blur)

- [x] **Шаг P3.1 — Бюджетирование FPS `PearlescentShader` + устранение бесконечного repaint `bb-avatar-float` (`PearlescentShader.jsx`, `ChatMessageCard.css`)**:
  - В `PearlescentShader.jsx` ограничить частоту отрисовки фоновых поверхностей до **24–30 FPS** (снижает нагрузку на iGPU в 4–5 раз на экранах 120–165 Гц без визуальной разницы) и полностью останавливать цикл `requestAnimationFrame` при `shaderStyle === 'off'`, `intensity <= 0`, скрытой вкладке или перекрытии сцены (`timelinesOpen` / шиты).
  - В `ChatMessageCard.css` убрать анимацию `box-shadow` из `@keyframes bb-avatar-float` (оставив только аппаратно-композитный `transform: translate3d(...)` и статичную тень), исключив непрерывный CPU/GPU `Paint` каждые 16 мс в покое.
  - **Живая проверка**: `Paint flashing` и `Performance` в DevTools в покое — `0` перерисовок на карточке сообщения и минимальное энергопотребление GPU.

- [x] **Шаг P3.2 — Изоляция композитинга `backdrop-filter` на боковых томах и `mask-image` на ленте чата (`WorkspaceLayout.css`, `ChatViewport.css`, `customizationDom.js`)**:
  - Добавить `contain: layout paint` на `.bb-tome`, `.bb-tome__body` и `.bb-chat-viewport__stage`, чтобы скролл в боковых томах не инвалидировала композитинг центральной сцены и наоборот.
  - Выставлять `backdrop-filter: none`, когда радиус размытия равен `0px` или непрозрачность поверхности равна `100%` (убирая холостой backdrop-root).
  - Оптимизировать краевое затухание `.bb-chat-viewport__stream` без тяжёлой перерисовки `@property` `mask-image` на всю высоту скролл-контейнера.
  - **Живая проверка**: замер плавности и энергопотребления при открытых обоих томах и одновременном скролле галереи и чата.

### Этап P4. Разгрузка главного потока Node.js (Серверная производительность на 800 карточках и 3 000 чатах)

- [x] **Шаг P4.1 — Вынос генерации PNG-миниатюр в `node:worker_threads` с очередью конкурентности и дедупликацией (`server/services/thumbnails.js`, `server/workers/thumbnailWorker.js`)**:
  - Вынести тяжёлый попиксельный декодинг и downscale PNG (`inflate` + Paeth unfilter + area-averaging + `deflate`) из главного потока Express в фоновый `Worker` с очередью конкурентности и дедупликацией параллельных запросов к одному и тому же файлу (`inFlightThumbnails` Map).
  - Заменить синхронные `fs.statSync / fs.readFileSync` в `ensureThumbnailFile` на асинхронные `fs.promises` + быстрый in-memory кэш проверенных путей.
  - **Живая проверка**: холодный скролл по 800 новым карточкам без миниатюр — Event Loop сервера остаётся полностью отзывчивым (`< 5 мс` на API-запросы), миниатюры генерируются плавно на фоновых ядрах CPU.

- [x] **Шаг P4.2 — Персистентный индекс карточек/чатов и LRU-ограничение памяти (`server/services/cardStore.js`, `server/services/chatJsonlCodec.js`)**:
  - Кэшировать сводный индекс карточек и статистику папок чатов на диске (`.nexustavern/index-cache.json` с проверкой `mtimeMs` и `size`), чтобы даже холодный старт сервера или завершение `stImporter` на 800 персонажах и 3 000 чатах не блокировали главный поток синхронным чтением тысяч файлов.
  - Ограничить размер `parsedChatCache` по принципу LRU (например, до 24 последних открытых полных `.jsonl` чатов), предотвращая бесконтрольный рост RAM при навигации по сотням чатов.
  - **Живая проверка**: холодный запуск сервера на базе 800 карточек / 3 000 чатов и мгновенный ответ `GET /api/characters` (`< 20–40 мс`).
