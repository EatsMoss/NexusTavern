# NexusTavern — План Оптимизации, Безопасности и Инженерных Стандартов

Данный документ фиксирует пошаговый план технических улучшений приложения **NexusTavern** по результатам аудита кодовой базы. Все работы проводятся в строгом соответствии с архитектурой и правилами из **[PROJECT.md](./PROJECT.md)**.

---

## 1. Исходные метрики и цели оптимизации

| Показатель | Текущее состояние (Baseline) | Целевое состояние (Target) |
| :--- | :--- | :--- |
| **Основной JS-бандл (`dist/assets/index-*.js`)** | `~1 438 КБ` (`~457 КБ` gzip), 1 монолитный чанк | `< 500 КБ` (`< 165 КБ` gzip) на старте + ленивые чанки по требованию |
| **Размер `AppShell.jsx`** | `7 407 строк`, хранит почти весь UI и бизнес-стейт | `< 900 строк` (чистая композиция в `src/app/` + доменные хуки) |
| **Мемоизация тяжёлых узлов (`React.memo`)** | `3` компонента во всём проекте | Полная изоляция `ChatMessageCard`, `MessageDecorator`, плиток галереи и боковых томов |
| **Ререндер при вводе текста в композер / стриминге** | Пересчёт всего `AppShell` и всех видимых карточек чата | Ререндер только поля ввода (при наборе) или только последней карточки (при стриминге) |
| **Фоновый поллинг `/api/system/status`** | Каждые `5 сек` синхронный обход 7 папок на диске + ререндер `AppShell` | Кэширование счётчиков по `mtimeMs` директорий, пауза в фоне, `0` холостых ререндеров |
| **Защита локального API и CSS-песочница** | Широкий `cors()`, пропуск `:root/html/body` в `<style>` сообщений | Строгий allowlist `Origin`, `timingSafeEqual`, 100% изоляция CSS карточек внутри `.bb-decorator-body` |
| **Статический анализ и автотесты** | Нет `jsconfig.json`, нет `ESLint`, `0` unit-тестов | `jsconfig.json` + `ESLint` (контроль границ слоёв) + автотесты критического ядра ST-совместимости |

## 2. Регламент выполнения плана

1. **Строгая атомарность**: каждый подшаг (`O1.1`, `O1.2` и т.д.) выполняется отдельно, без смешивания рефакторинга и новых фич.
2. **Никаких регрессий совместимости**: 100% обратная совместимость с форматами SillyTavern (`chara`/`ccv3`, `.jsonl`, пресеты, `RegexScriptData`, `settings.json`) неприкосновенна.
3. **Обязательная живая проверка после каждого шага**: после завершения каждого шага работа останавливается, предоставляется отчёт, и изменения тестируются вживую в браузере (ПК / мобильный вид) перед переходом к следующему шагу.
4. **Никаких лишних зависимостей**: используем нативные возможности браузера, React 19, Vite 6 и Node.js без раздувания `node_modules`.

## 3. Пошаговый план работ

### Этап O1. Безопасность, Криптография и Изоляция стилей (Быстрые точечные правки)

- [x] **Шаг O1.1 — Ограничение политики CORS для защиты локального сервера (`server/index.js`)**:
  - Заменить открытый `app.use(cors())` на динамическую проверку `Origin`: разрешать запросы только с локальных адресов (`localhost`, `127.0.0.1` на портах сервера и Vite), адресов локальной подсети (LAN) и домена активного SSH-туннеля.
  - Заблокировать кросс-доменные запросы с посторонних веб-сайтов в браузере ПК к `http://127.0.0.1:8088/api/*`.
  - **Живая проверка**: работа приложения на `localhost:5173`, `localhost:8088` и через мобильный туннель без CORS-ошибок; блокировка запроса с чужого `Origin`.

- [x] **Шаг O1.2 — Закаливание криптографии и кэширование ключа E2EE (`server/utils/auth.js`, `src/core/api/apiClient.js`)**:
  - На сервере перевести проверку заголовка `X-BB-Auth` и query-параметра `auth` на константное по времени сравнение `crypto.timingSafeEqual`.
  - На клиенте (`apiClient.js`) кэшировать импортированный объект `CryptoKey` (`AES-GCM`) и вычисленный `authIdHex` в памяти по текущему `masterKeyHex`, убрав повторные вызовы `crypto.subtle.importKey` и `digest('SHA-256')` на каждый HTTP-запрос и чанк SSE-потока.
  - **Живая проверка**: сканирование QR-кода туннеля с телефона, отправка сообщений и SSE-стриминг с включённым `E2EE`, ротация ключа туннеля.

- [x] **Шаг O1.3 — Строгая песочница пользовательских `<style>` в сообщениях (`src/core/messages/messageHtml.js`)**:
  - В `prefixSimpleSelector` заменять глобальные селекторы `:root`, `html`, `body` на локальный контейнер `.bb-decorator-body` вместо оставления их без префикса.
  - Блокировать внешние директивы `@import` внутри пользовательских `<style>` (и `url(...)` при отключённом `allowExternalMedia`), сохранив корректную работу `@keyframes` и `@media` в оформлении богатых RP-карточек.
  - **Живая проверка**: рендер карточек со сложной HTML/CSS-вёрсткой и проверка, что `<style>:root { ... } body { ... }</style>` внутри сообщения не влияет на оболочку NexusTavern.
